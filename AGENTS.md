# AGENTS.md — canonical rules for this repository

**This file is the single source of truth for how to work in `pshyapp`.** `CLAUDE.md` and
`GEMINI.md` beside it are pointers to this file. Each folder has its own `AGENTS.md` with local
detail; where a folder file and this one disagree, **this one wins.**

Last verified against the working tree: **2026-08-26.**

---

## The one thing to get right

There are two folders. They have opposite rules.

| Folder | What it is | What you may do |
|---|---|---|
| **`anatomy-explorer/`** | **The product.** All new work happens here. | Build. This is the build target. |
| **`patient-library/`** | **Live, and reference-only.** Deployed on Vercel, a physiotherapist is entering clinical content into it, patients have the link. | **Read. Copy out of. Never edit. Never delete.** |

`patient-library/` is not deprecated and it is not being removed. It is the working reference and
the rollback target (A-011). Treat it as a library you have source access to: read it, learn the
contract, copy code into `anatomy-explorer/`, and leave the original untouched.

If a task seems to require editing `patient-library/`, that is the signal to stop and ask. There
is no routine reason to write there.

## The seven non-negotiables

These apply in both folders and to every tool.

1. **Content lives in the Google Sheet, not in the repo.** `src/data/areas.json` and
   `items.json` are generated by `npm run sync:content`. Hand-editing them puts the repo out of
   step with the sheet and the next sync silently reverts you. **A content change is a sheet
   change.** See `patient-library/docs/CONTENT-SCHEMA.md` for the contract.

2. **Never invent clinical content.** Exercise names, instructions, dosages, target muscles and
   safety lines come from the physiotherapist. Anything clinical you add ships as `status: draft`
   with empty `reviewed_by` and `reviewed_date`. **Never write a clinician's name or a review
   date.** If something looks clinically wrong, **flag it — do not fix it.**

3. **Never relax the compliance check.** `patient-library/src/lib/compliance.ts` holds 52
   word-boundary rules — 8 superlatives, 4 outcome claims, 5 booking CTAs, 36 condition names —
   enforcing the DHA advertising standards, the MOHAP booking-CTA rule and the no-condition-names
   rule. A build that goes green because a rule was loosened has removed the product's core legal
   constraint, silently and invisibly. **Fix the content, never the check.**

4. **Do not touch config or lockfiles as a side effect.** `astro.config.mjs`, `package.json`,
   `package-lock.json`, `tsconfig.json`, `.github/`. An agent deleted `astro.config.mjs` while
   working on something else and nobody noticed for days — that is how the Vercel adapter and the
   sitemap went missing. If your task genuinely needs a config change, **say so and stop.**

5. **Navigation is by body area, never by condition.** Decision D-001, and it is the clinician's
   own call. No diagnosis language anywhere — including comments, identifiers, filenames and
   commit messages.

6. **No analytics, accounts, tracking or backend.** Decision D-007. This is why the Vercel
   `webAnalytics` flag is not coming back. Two `localStorage` keys are permitted (last chosen
   area, text size) and nothing else.

7. **17px base font. Areas sort head to toe, never alphabetically.** Decision D-014.

## How to use `patient-library/` as a reference

It is authoritative for these things. When `anatomy-explorer/` needs one of them, **copy the file
in and adapt it there** — do not reach across the folder boundary at runtime (see the trap below).

| What you need | Read this | Note |
|---|---|---|
| The sheet contract — every column the clinician fills | `docs/CONTENT-SCHEMA.md` | Authoritative. Do not infer the schema from the JSON. |
| What the clinician actually sees and does | `docs/SHEET-GUIDE.md` | **She is working from this document right now.** If you change the pipeline, this document must stay true. |
| The compliance rules | `src/lib/compliance.ts` | The one real implementation. Import it; never re-implement it. |
| Cross-row content rules | `src/lib/validate.ts` | Duplicate ids, area over-capacity, orphan items, image/area mismatch, 45-char alt-text floor. |
| Why anything is the way it is | `memory.md` — decisions **D-001..D-028** | Read before deciding. `anatomy-explorer/memory.md` cites `D-###` and means this file. |
| The evidence base | `docs/RESEARCH-FINDINGS.md` | Backs D-007, D-008, D-009, D-012 and the footer's eight regulatory disclosures. |
| Required legal disclosures | `src/components/SiteFooter.astro`, `src/content/legal/` | The disclaimer is a launch dependency. Servier attribution in `credits.md` is a licence condition. |
| Design tokens | `src/styles/tokens.css` | Carries the 17px base and the `--scale` multiplier. Wins over `anatomy-explorer/src/styles/global.css`. |
| Route and template shape | `src/pages/[section].astro`, `src/pages/[section]/[area_id].astro` | Head-to-toe ordering and the item card's locked field order. |
| The clinician's own written spec | `PRD.md`, `BUILD-PLAN.md` | BUILD-PLAN's approval gates are why content production is staged. |

### Never copy these out

- **`add-lowerback.js`** — hand-authors clinical content, including dosages and safety lines. A
  working example of the one prohibited pattern. It is also where the `lower-back` / `lowerback`
  image-id mismatch on four items came from.
- **`astro.config.mjs` as it exists at git `HEAD`** — contains `webAnalytics: { enabled: true }`,
  a direct D-007 violation, plus `site: 'https://example.com'`. Write a fresh config; do not
  `git checkout` that one.
- **`public/sw.js`** — unregistered dead code, cache-first with no versioned invalidation. Wired
  up as-is it would serve a retired exercise indefinitely.
- **The `openai` dependency** — a production dependency imported by nothing.
- **`patient-library/README.md`'s Astro boilerplate advice** — it recommends React and Tailwind,
  neither of which this project uses, and the flag `astro dev --background`, which is not a real
  Astro flag. That boilerplate is the origin of `anatomy-explorer`'s broken `dev` script.
- **`HANDOFF.md`** — declares "no application code yet" against 33 source files.

### The cross-boundary trap, and it is live right now

`anatomy-explorer/src/lib/library.ts` currently begins:

```ts
import areasData from '../../../patient-library/src/data/areas.json';
import itemsData from '../../../patient-library/src/data/items.json';
```

Do not add more of these, and replace this one. Three reasons, in the order they bite:

1. **It cannot deploy.** Vercel with Root Directory set to `anatomy-explorer` never uploads
   anything above that directory, so the build fails before it starts.
2. **It skips every safety layer.** It casts raw JSON with `as LibraryArea[]`, so this data
   reaches patients having passed no Zod schema, no `validate.ts` and no compliance gate.
3. **It couples the two folders permanently**, which is the opposite of the reference
   relationship described above.

The fix is to port the data files, the Zod schemas and the compliance pipeline into
`anatomy-explorer/`, then delete the relative import. `anatomy-explorer/PORT-CHECKLIST.md` lists
every file, in order, with its known defects.

## Read order for a tool that is new here

1. This file.
2. `anatomy-explorer/AGENTS.md` — the build target's local rules.
3. `anatomy-explorer/PORT-CHECKLIST.md` — what to bring across, tiered by consequence, with the
   defect to fix on each. **Start here rather than re-deriving the inventory.**
4. `anatomy-explorer/memory.md` — decisions **A-001..A-014**. A-011 supersedes A-001; A-012 makes
   full-body 3D the signature experience; A-013 archives the old module briefs; A-014 defines the
   three entry points.
5. `patient-library/docs/MERGE-PLAN.md` — the merge spec: route map, region→area resolution,
   port/retire tables. Two of its claims are wrong; see the note in PORT-CHECKLIST.
6. `patient-library/memory.md` — decisions **D-001..D-028**.

Append a decision entry to the relevant `memory.md` when you make a real decision. **Never
silently reverse an old one** — write a new entry that supersedes it, the way A-011 supersedes
A-001.

## Verified state, 2026-08-26

Believe this section over any other document's status header; several are stale by weeks.

**Git — read this before running anything destructive.** The split into these two folders was done
with plain `mv` and **never committed**. `git ls-files` returns **zero** for both folders, so
neither has an ancestor in any commit. `git clean -fd` would erase the product with no reflog
entry. **Never run `git clean -fd`, `git clean -fdx`, or `git checkout -- .` at this repo root
until both folders are committed.** `git reset --hard` is survivable; `git clean` is not.
Committing both trees is the highest-value action available in this repo.

**`anatomy-explorer/`.** The A-014 shell exists — a home page with three entrances, plus
`/find-my-area/`, `/stretching/` and `/exercises/`. Underneath it: the section index cards all
404 because `[area_id].astro` has not been ported; the locator dead-ends, with only a home link
and a skip link; `body-regions.ts` never gained the `stretching_area_id` / `exercise_area_id`
columns that MERGE-PLAN's region→area resolution depends on; `astro.config.mjs` is five lines
with no Vercel adapter and a placeholder domain; and `package.json` declares only `astro` and
`typescript`, so the pipeline's dependencies are all absent.

**`patient-library/`.** Live, but serving **zero images** — `image_status` is unset on all 26
items and `ExerciseImage.astro` correctly refuses to render an unapproved image, so patients see
text only. Also: seven compliance errors currently block `prebuild`, and there is no
`astro.config.*` in the folder, so it cannot build locally either. The deployed site is fine
because Vercel builds from `origin/main`, which still holds the old flat structure.

**Content.** 16 areas and 26 clinician-authored items exist; 5 items are published and 21 are
draft. That clinical work is irreplaceable and is the reason rule 2 exists.

**CI is red and will stay red.** `.github/workflows/ci.yml` runs at the repository root, where
there is no longer a `package.json`. It also runs `npm run lint`, and `eslint.config.mjs` was
deliberately removed. Fix the workflow deliberately, as its own task — not as a side effect.

**A naming trap that will cost someone an hour.** `section` in the data is `exercise`, singular.
The shell hardcodes `/exercises/`, plural. Porting `[section]/[area_id].astro` unchanged emits
`/exercise/neck/` while the index cards link to `/exercises/neck/`. `stretching` is unaffected,
which is exactly why it gets missed. Decide once, in one place, and write it down.

## Two environment notes

**Git writes fail over the Claude device bridge.** `.git/index.lock` is not writable on the
mount. Run every git command from a real terminal.

**Builds cannot run over the bridge either.** `node_modules` holds Windows native bindings and
the bridge shell is Linux, so `build`, `lint` and `typecheck` all fail there for reasons that
have nothing to do with the code. **Say so honestly rather than reporting a check as passed.**
